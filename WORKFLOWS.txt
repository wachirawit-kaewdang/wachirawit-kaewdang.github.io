Maintaining the portfolio
=========================
Print this file with: npm run help
Needs Node ^20.19.0 or >=22.12.0, and npm ci run once.

Everyday
--------
npm run dev       Dev server at http://localhost:5173 (the appendix is at #/cs403).
npm run lint      oxlint over the source.
npm run verify    Everything CI runs before deploying, in the same order. The notebook
                  comparison needs ../Project-CS403 (or CS403_REPO), and says so if skipped.
npm test          Tests the calculations in src/metrics.js.
npm run test:extractor  Tests the extractor's parsing on made-up notebook output.
npm run check     Checks a build cannot catch (see "What CI checks" below).
npm run render-check  Opens the built site in headless Chrome; run npm run build first.
npm run build     Production build to dist/. Fails if index.html keeps a %NAME% placeholder.

Content lives in src/data.js. The CS403 tables and quoted counts are computed by src/metrics.js
from src/metrics.json. Some claims are still typed; they are listed under "The CS403 results
are frozen" below.

Deploying
---------
Push to main. GitHub Actions (.github/workflows/deploy.yml) runs npm ci, lint, both test
suites, check, the notebook comparison, build and render-check, then publishes dist/ to GitHub Pages. Pull requests, and manual runs on other branches,
run the same steps but never deploy.

The CS403 results are frozen
----------------------------
The site reports the notebook at commit 0c4ef04, and the check fails on any other commit. Do
not rerun the notebook to refresh numbers: it sets no random seeds and downloads live prices,
so a rerun changes everything. An improved run belongs in a new section beside these results,
not on top of them.

To confirm the numbers still match the notebook (needs Python 3.10+):
  python scripts/extract-metrics.py <path to Project-CS403>
  git diff src/metrics.json        (should show nothing)
It reads the notebook's saved outputs by column name, cross-checks its tables and rewrites
src/metrics.json. Nothing is re-executed. sectorShap is kept as is, because the notebook saved
it only as sector_shap.png; its bond-yield bars are checked against the per-stock table.

If the results are ever moved to a new commit, all of this is by hand, before changing
frozenAt in scripts/checks/metrics.mjs:
- Replace the charts in public/cs403/ and re-read sectorShap from sector_shap.png and
  rankGap from rank_disagreement_summary.png. The extractor keeps both, and their hash alone
  won't tell you they're out of date.
- Re-read the typed claims in src/data.js, src/ProjectCS403.jsx and resume/resume.html:
  "5 to 12 positions", the features that moved most, 27 features, "close to chance",
  "close to a coin flip", which sector leans on what, the bond-yield reading, and the model
  setup (layers, window, dates).
- If the check says the resume should quote a new number, confirm that number against the
  notebook first. The check only compares them; it cannot tell which one is right.

Rebuilding the resume PDF
-------------------------
Edit resume/resume.html, then: npm run resume
Prints it to public/Wachirawit_Kaewdang_Resume.pdf with the installed Chrome or Edge (set
CHROME=/path/to/chrome to pick another). It fails if a font file is missing or no new PDF is
written, and records both files' hashes in resume/resume.sha256. Commit all three; the check
fails if the HTML or PDF changes without a rebuild.

Rebuilding the link-preview image
---------------------------------
With npm run dev running, capture http://localhost:5173/og/og-image.html at 1200x630 with any
headless Chrome screenshot and save it as public/og-image.png. Its words are typed into
og/og-image.html, so update them when the name, role or summary in src/data.js changes.

What CI checks (npm run verify, plus the notebook comparison)
------------------------------
- Every file the site links to exists in public/: resume, figures, favicon, og:image.
- metrics.json is at the frozen commit, with 10 stocks, 5 sectors of 10 rows and every rate in
  [0, 1].
- The 0.30-threshold stocks have F1 equal to always-up, 2p / (1 + p); the others do not.
- resume/resume.html quotes the computed CS403 numbers, and the PDF was built from it.
- metrics.json is exactly what the extractor rebuilds from the notebook at its frozen commit.
  sectorShap's values came from a chart, so only its bond-yield bars are compared.
- sectorShap, rankGap and the source block match a pinned hash, the charts and share image
  match pinned file hashes, and Table 1's computed results match
  fixed expected values in scripts/checks/metrics.mjs. If the freeze ever moves, both must be updated.
- The resume PDF is one page and uses only STIX Two Text.
- The resume and og/og-image.html contain the contact details in src/data.js. If you change
  the site address, rebuild og-image.png too; the check reads only its HTML source.
- After the build, both pages render in headless Chrome with no literal NaN or undefined.
